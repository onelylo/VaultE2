SECTION 1: ARCHITECTURAL OVERVIEW & DEEP-DIVE LOGIC
--------------------------------------------------------------------------------

1. HYBRID MEDIA ROUTING (P2P Mesh vs. SFU)
   To match WhatsApp's instant responsiveness and low latency for 1:1 calls while 
   competing with Discord's massive multi-user voice channels and screen shares, 
   VaultChat utilizes a hybrid dual-engine approach:

   A. 1:1 Calls (Direct WebRTC Mesh):
      - Audio and video packets flow directly between Peer A and Peer B via RTCPeerConnection.
      - Zero media server bandwidth or latency overhead.
      - NAT Traversal is resolved using Coturn (STUN/TURN) servers over TLS (TURNS) 
        to ensure connection success across strict firewalls and mobile networks.

   B. Group Channels & Screen Streams (Selective Forwarding Unit - SFU):
      - Uses Mediasoup (a C++ media engine bound to Node.js).
      - Unlike traditional MCU media servers that decode, re-encode, and mix streams 
        (costing extreme CPU usage), an SFU acts as a ultra-low-latency router.
      - It receives raw RTP streams from producers and selectively forwards them to 
        consumers without decoding media payloads.
      - Supports SVC (Scalable Video Coding) in VP9/AV1 codecs: a single stream is sent 
        with multiple spatial/temporal layers (e.g., 1080p, 720p, 360p). The SFU dynamically 
        routes lower resolution layers to users with constrained bandwidth without 
        re-encoding.

2. ZERO-TRUST END-TO-END ENCRYPTION (SFrame & Insertable Streams)
   - Standard WebRTC encrypts packets in transit using DTLS-SRTP, but the SFU 
     server usually holds the decryption keys.
   - To adhere to VaultChat's Zero-Trust policy, media uses WebRTC Insertable Streams 
     (RTCRtpScriptTransform / WebCodecs).
   - Audio (Opus) and Video (AV1/VP9) frames are intercepted on the client *before* 
     packetization.
   - Frames are encrypted using AES-256-GCM using client-side keys negotiated via 
     ECDH (Elliptic Curve Diffie-Hellman).
   - The SFU routes encrypted ciphertext. The server cannot inspect or record audio/video.

3. EXTREME PERFORMANCE & LOW RESOURCE CONSUMPTION
   - CPU & Battery Optimization: When video stream tabs are minimized or off-screen, 
     the client automatically scales incoming frame rates down to 5 FPS.
   - Hardware Acceleration: Enforces hardware-accelerated H.264/AV1 codecs via 
     NVENC, QuickSync, or VideoToolbox to bypass software CPU encoding.
   - Dynamic Opus Bandwidth Adaptation: Speech scales dynamically between 16 kbps 
     (crisp voice) and 64 kbps (high-fidelity audio) with built-in noise suppression 
     (RNNoise / WebRTC AEC).
